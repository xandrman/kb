# Синтетические сервисные акты: как сгенерированы

Справочный документ. Не ADR, решений не фиксирует и на ADR не ссылается. Описывает, как собран
компонент 1 пилотного корпуса (ТЗ, п. 4.5) — 50 синтетических актов сервисного обслуживания с ПДн —
и как повторить генерацию.

## Итог

| | |
|---|---|
| Где лежат | `testdata/synthetic/` (каталог в `.gitignore`, в репозиторий не попадает) |
| Состав | 50 актов: 40 PDF, 5 PNG, 5 JPEG; каждый на одну страницу |
| Метаданные | `testdata/synthetic/manifest.json` |
| Шаблон | `docs/templates/akt-servisnogo-obsluzhivaniya.html` |
| Генератор | artisan-команда `testdata:service-acts` (`backend/app/Console/Commands/GenerateServiceActs.php`) |
| Грифы | 43 служебных, 7 конфиденциальных |
| Типы обслуживания | 31 гарантийный ремонт, 16 платных, 3 диагностики |

## Шаблон

Форма акта снята с публичной фотографии реального акта сервисного центра: взята только структура
(шапка организации, таблица из 10 строк, описание работ, типовой текст о приёмке, подписи).
ПДн клиента, имя сотрудника, реквизиты и брендинг исходного документа не перенесены — все значения
заменены плейсхолдерами `{{name}}`, их список с пометками ПДн — в комментарии в `<head>` шаблона.

ТЗ (п. 11) предполагает форм-шаблоны от Заказчика; этот шаблон — временная замена, пока их нет.
Из четырёх форм п. 4.5 сделан только акт сервисного обслуживания.

Особенности под рендер dompdf:
- шрифт DejaVu Sans — в нём есть кириллица;
- строка подписей — таблица, dompdf не поддерживает flexbox;
- комментарий стоит после `<meta charset="UTF-8">`: длинный комментарий перед ним ломает определение
  кодировки, и кириллица в PDF превращается в «кракозябры».

## Откуда берутся значения

| Поля | Источник |
|---|---|
| Модель техники (SKU) | Имена файлов публичного корпуса `testdata/registry.json`: регулярное выражение `SNR-…`, только файлы до 52 страниц, без масок серий (`XXXX`). Каждый акт — своя модель, 50 моделей на 50 актов |
| Товар, неисправность со слов потребителя, описание работ, результат | Локальная LLM (`kb-vllm-generate`) через агента `App\Neuron\ServiceActWriter`, structured output `App\Neuron\Output\ServiceActContent`, temperature 0.9. На вход — модель и тип обслуживания |
| ФИО, адрес, телефон, e-mail клиента; ФИО представителя | Faker, локаль `ru_RU`. Телефоны `+7(9##)###-##-##`, e-mail на `example.com`/`example.org`. Представителей четверо, повторяются между актами |
| Организация | Вымышленное ООО «ТехноМарт»; ИНН и КПП — случайные цифры без контрольной суммы, адреса — Faker |
| Тип обслуживания | Случайно с весами 6 : 3 : 1 — гарантийный ремонт, платный ремонт, диагностика |
| Номер и дата акта, даты приёма и выдачи | Faker: дата акта 01.01.2025–31.08.2026, приём на 1–20 дней раньше, срок обслуживания = разница дат |
| Серийный номер | Faker, формат `ААА-##########` |
| Гриф | 20 % конфиденциальных, остальные служебные |

Ограничения длины (жалоба до 15 слов, описание работ до 30, результат до 5) заданы в инструкции агента:
описания полей схемы модель игнорировала, и акты растягивались на две страницы.

## Манифест

`manifest.json` — массив, по записи на акт:

| Поле | Содержание |
|---|---|
| `filename` | Имя файла в `testdata/synthetic/` |
| `sku`, `document_type`, `access_level`, `owner_department`, `document_date` | Метаданные для загрузки (ТЗ, п. 4.2, 9.3); `access_level` — значения `App\Enums\AccessLevel` |
| `personal_data` | Все ПДн акта: тип (`App\Enums\PersonalDataType`) и значение — эталон для проверки guardrails (FR-8) |
| `related` | Файлы публичного корпуса с той же моделью в имени — эталон для multi-hop (п. 8.2) |
| `fields` | Все значения, подставленные в шаблон |

## Повторение генерации

PHP на хосте нет, Sail не запущен — команда запускается в образе `kb-app` с примонтированным
репозиторием (dev-зависимости берутся из `backend/vendor`) в сети `kb-internal`, где доступен vLLM:

```bash
docker run --rm --network kb-internal --user "$(id -u):$(id -g)" \
  -v /home/xandrman/kb:/repo -w /repo/backend \
  -e APP_KEY="base64:$(head -c32 /dev/urandom | base64)" \
  -e LLM_URL=http://kb-vllm-generate:8000/v1 -e LLM_MODEL=default -e OTEL_SDK_DISABLED=true \
  --entrypoint php "$(docker inspect kb-app --format '{{.Image}}')" \
  artisan testdata:service-acts
```

Опции: `--count` (50), `--seed` (2026), `--template`, `--registry`, `--out` — по умолчанию пути выше.

При том же `--seed` повторяются модели, ПДн, даты, номера и грифы; тексты LLM — нет.
Повторный запуск перезаписывает PDF и `manifest.json`: сканы (ниже) придётся сделать заново.

Зависимость рендера — `barryvdh/laravel-dompdf` в `require-dev` (как и Faker): в production-образе
команда не работает.

## Сканы

10 актов переведены из PDF в изображения — для проверки приёма PNG/JPEG (п. 4.1) и OCR (FR-2).
PDF-версии этих актов удалены, в манифесте указаны новые имена: дубли с одинаковым текстом
мешали бы поиску и подсчёту ПДн.

| Формат | Акты | Конфиденциальные |
|---|---|---|
| PNG | 001, 006, 012, 023, 036 | 023 |
| JPEG, качество 80 | 010, 018, 020, 042, 044 | 020 |

Выполнено на хосте Ghostscript и ImageMagick: растр 200 dpi в оттенках серого, поворот 0.4–0.9°
в разные стороны, шум, лёгкое размытие, оттенок бумаги.

```bash
gs -q -dNOPAUSE -dBATCH -dSAFER -sDEVICE=pnggray -r200 -sOutputFile=raw.png service-act-006.pdf
convert raw.png -background white -rotate 0.5 -attenuate 0.35 +noise Gaussian -blur 0x0.5 \
  -level 8%,97% -fill '#f3f1ea' -colorize 6% service-act-006.png          # для JPEG: -quality 80 … .jpg
```

Подписей, печатей и рукописных полей в сканах нет.

## Известные недостатки

- Модели извлекаются из имён файлов неточно в двух случаях: `SNR-ERD` — название серии из имени
  презентации, `SNR-UPS-ONRT-1` — обрезанное `ONRT-1,2,3`. Их `related` и название модели в акте неточны.
- LLM иногда ошибается с видом устройства: в акте 020 «Инвертор SNR-ERD-2.3», хотя это контроллер
  мониторинга. Вид устройства в запрос не передаётся — LLM угадывает его по модели.
- Почти все результаты — «Отремонтирован» (46 из 50); отказов в гарантийном ремонте нет.
- В строке подписей линия подписи представителя переносится на следующую строку.
- Каждый PDF ~870 КБ: dompdf встраивает шрифт целиком.
