# ADR-0002: Взять Grafana OSS как единый слой наблюдаемости

Статус: принят  
Deciders: AI Architect  
Дата: 2026-09-19  
Техническая история: ТЗ-ТМ-2026-014, п. 5 (FR-9), 7.9, 8.4

## Контекст

FR-9/7.9: сквозной трэйс запроса (вопрос → ретривал → агент → генерация) и метрики (токены/сек, TTFT, RPS, GPU/VRAM) на дашбордах; трэйс виден в инструменте трейсинга (8.4). Наблюдаемость = метрики + логи + трейсинг, все три столпа. Ограничения: закрытый контур (SaaS исключён, п. 6.3), нет DevOps в штате (п. 2.2), сегментация DMZ/Internal (п. 6.4). Источники телеметрии: Prometheus (метрики), Loki (логи), Tempo (трейсы).

## Варианты

| | Суть |
|---|---|
| **A. Grafana OSS** | Одна панель: Prometheus + Loki + Tempo; alerting; provisioning; self-hosted |
| B. ELK (Kibana) | Сильный лог-стек, но тяжёлый (JVM/Elasticsearch), трейсинг сторонним инструментом |
| C. SigNoz | All-in-one на OpenTelemetry, меньше зрелая экосистема |
| D. Zabbix | Инфра-мониторинг, слабый с логами/трейсами/LLM-метриками |
| E. SaaS (Datadog, …) | Нарушает п. 6.3/152-ФЗ — **исключён** |

## Решение

**Вариант A.** Grafana OSS — единый слой визуализации и алертинга; data sources — Prometheus, Loki, Tempo. Развёрнут как контейнер `kb_grafana` в сегменте **Internal** (сеть `kb_internal`), без публикации host-портов; наружу — только через reverse proxy в DMZ.

**Лицензия.** Grafana OSS — **AGPL-3.0**: допустимо, т.к. сервис автономен и copyleft не распространяется на код Платформы; модификации/редистрибуция не допускаются — используем дистрибутив как есть.

## Последствия

Плюс:
- Одна UI для FR-9: трэйс + TTFT/токены-сек/RPS/GPU-метрики на одном дашборде
- Алертинг по данным разных источников
- Provisioning дашбордов/data sources/ролей как код (продолжение ADR-0001)
- Встроенный RBAC (Viewer/Editor/Admin, service accounts)

Минус:
- AGPL-3.0: нет редистрибуции модификаций (на код Платформы не влияет)
- HA в MVP нет; алертинг — contact points без группировки/эскалации (это Alertmanager)
