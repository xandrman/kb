# ADR-0033: Сертификат TLS периметра — файлы оператора в `infra/tls/` вместо выпуска через ACME

Статус: принят  
Deciders: AI Architect  
Дата: 2026-09-24  
Техническая история: ТЗ-ТМ-2026-014, п. 1.2, 6.3, 6.4, 8.1, 11

## Контекст

TLS на внешнем периметре завершает nginx (сеть `kb-dmz`) на портах 443, 8001, 8002 и 8003 для одного домена `domain_name`. До этого решения сертификат выпускался в Let's Encrypt двумя контейнерами certbot. Разовый `kb-certbot-init` выпускал сертификат в standalone-режиме на порту 80 хоста до старта nginx, долгоживущий `kb-certbot` раз в сутки продлевал его через webroot, который отдавал nginx. Сертификат лежал в томе `kb-certbot-data`, nginx читал его оттуда.

Отдельным ADR эта схема не оформлялась и работает только на стенде: ACME HTTP-01 требует исходящего доступа к серверу Let's Encrypt и входящего доступа из интернета на порт 80. Платформа же обязана работать полностью автономно (1.2, 6.3), а приёмка проверяет конвейер без доступа в интернет (8.1). В закрытом контуре Заказчика публичный центр сертификации недоступен: сертификат выдаёт корпоративная PKI Заказчика.

## Драйверы

- **Закрытый контур (1.2, 6.3, 8.1).** Развёртывание не должно зависеть от внешнего центра сертификации, а периметр не должен держать порт 80 открытым для внешнего ACME-челленджа.
- **Сертификат выдаёт Заказчик.** Доверие к сертификату в браузерах сотрудников обеспечивает корпоративная PKI, а не публичный CA; формат выдачи — пара PEM-файлов.
- **Закрытый ключ не попадает ни в git, ни в state Terraform (6.4).** State хранится в открытом виде и копируется вместе с каталогом `infra/`.
- **nginx не стартует без сертификата.** Ошибка должна проявляться до создания контейнера, а не циклом перезапусков.
- **Меньше движущихся частей (2.2).** Команда эксплуатации — PHP-разработчики без DevOps-специалиста.

## Варианты

| | Суть |
|---|---|
| **A. Файлы оператора в каталоге хоста** | `infra/tls/fullchain.pem` и `privkey.pem` кладёт оператор, каталог подключается в nginx только на чтение; certbot удаляется |
| B. Оставить certbot и Let's Encrypt | Автопродление на стенде; противоречит 1.2 и 8.1, в контуре Заказчика не работает |
| C. Внутренний ACME-сервер в контуре (step-ca и т. п.) | Автопродление без интернета; цена — ещё один сервис с собственным корневым ключом, который надо встроить в PKI Заказчика |
| D. Сертификат через переменную Terraform (`upload`) | Контейнер пересоздаётся при смене сертификата сам; цена — закрытый ключ в state и в `tfvars` |
| E. PKI-движок Vault | Выпуск и ротация из выделенного сервиса секретов (6.4); Vault в стеке ещё не развёрнут |

## Решение

**Вариант A.**

- Сертификат домена хранится на хосте в `infra/tls/`: `fullchain.pem` (сертификат и промежуточные) и `privkey.pem`. Имена файлов не зависят от домена.
- Каталог целиком исключён из git (`.gitignore`). Права на ключ — `600`.
- nginx получает каталог bind mount'ом только на чтение по пути `/etc/nginx/tls` (`infra/edge.tf`). Ключ в state Terraform не попадает: Terraform передаёт путь, а не содержимое.
- Перед созданием `kb-nginx` Terraform проверяет наличие обоих файлов (`precondition`) и останавливает `apply` с понятной ошибкой, если их нет.
- Контейнеры `kb-certbot-init` и `kb-certbot`, тома `kb-certbot-data` и `kb-acme-webroot` удаляются. На порту 80 nginx только перенаправляет на HTTPS.
- Замена сертификата: оператор кладёт новые файлы в `infra/tls/` и выполняет `docker exec kb-nginx nginx -s reload`. Пересоздавать контейнер не требуется.
- На стенде в `infra/tls/` перенесён действующий сертификат Let's Encrypt из тома `kb-certbot-data`.

## Последствия

Плюс: развёртывание больше не требует доступа к Let's Encrypt и открытого из интернета порта 80 — одна из внешних зависимостей закрытого контура снята; сертификат корпоративной PKI Заказчика подключается без изменения конфигурации; ключ не хранится ни в git, ни в state; два контейнера и два тома меньше; отсутствие сертификата видно на этапе `apply`.

Минус: автопродления нет — сроки действия отслеживает оператор, иначе периметр перестанет открываться в браузерах; сертификат Let's Encrypt на стенде действует до 22.12.2026 и дальше не продлевается; `infra/tls/` — состояние хоста вне Terraform и вне git, его надо переносить и резервировать вместе с сервером; reload nginx после замены — ручной шаг.

Упоминание `kb-certbot-init` в ADR-0032 (перечень разовых init-контейнеров) теряет предмет; решение ADR-0032 от этого не меняется.

Точка ревизии — развёртывание Vault (6.4): тогда выпуск и ротация сертификата периметра переносятся в его PKI-движок (вариант E), а ручная замена файлов заменяется автоматической.
