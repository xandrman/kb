# ADR-0020: Фреймворк прикладного слоя — Laravel 13

Статус: принят  
Deciders: AI Architect  
Дата: 2026-09-22  
Техническая история: ТЗ-ТМ-2026-014, п. 2.2, 5 (FR-1, FR-5, FR-6, FR-7, FR-8, FR-9), 6.1, 6.3, 6.4, 7.1, 7.6, 7.8, 7.9, 7.10

## Контекст

П. 7.6 фиксирует PHP 8.x для трёх компонентов — MCP-сервер, админ-панель, RAG-конвейер — и не называет фреймворк. Ни один из ADR-0001–0019 его не выбирал, но три записи уже опираются на существование прикладного слоя: ADR-0018 монтирует том в «контейнеры PHP-слоя» и требует интерфейс blob-хранилища, ADR-0014 — подключение под RLS отдельной ролью, ADR-0012 — воркер, отправляющий файл в docling-serve по HTTP.

Форма поставки задана п. 7.8: Платформа предоставляется как MCP-сервер, встраиваемый в существующую систему диалогов. Основной внешний контракт — MCP-эндпоинт, а не HTML-интерфейс.

## Драйверы

- **MCP-сервер — обязательство поставки (7.8), а не деталь реализации.** `laravel/mcp` — first-party пакет (MIT, v1.0.0 от 14.09.2026, PHP ^8.2): транспорт, JSON-RPC, JSON-схемы инструментов, тестовые ассерты, `mcp:inspector`. Вне Laravel серверная сторона MCP собирается на сторонних пакетах, чей жизненный цикл с фреймворком не связан.
- **Streaming (FR-6) даёт тот же пакет.** `handle()` возвращает `Generator`, и для web-сервера каждый `yield` уходит событием SSE. Без этой механики поток токенов vLLM (ADR-0008) до клиента MCP не доходит — ответ отдаётся одним сообщением.
- **FR-1 — асинхронная обработка с видимым статусом.** Очереди, планировщик, миграции, валидация и Eloquent идут с фреймворком. За docling-serve (ADR-0012) с его собственной RQ-очередью остаётся только извлечение; стадии FR-3 и FR-4 — задачи Laravel на том же Redis (ADR-0019).
- **Окно поддержки перекрывает приёмку и первый год сопровождения (2.2).** Laravel 13 — релиз 17.03.2026, исправления ошибок до Q3 2027, безопасность до 17.03.2028; PHP 8.3–8.5.
- **Air-gapped (6.3).** Зависимости ставятся composer'ом на этапе сборки образа; ни один используемый first-party пакет не обращается наружу в рантайме. Лицензия MIT.

## Варианты

| | Суть |
|---|---|
| **A. Laravel 13** | First-party MCP-сервер со streaming через SSE, очереди, планировщик, миграции; цена — объём фреймворка и мажорный релиз раз в год |
| B. Symfony 7.x | Сопоставим по возможностям, Messenger вместо Queue; серверная сторона MCP — сторонний пакет; выше порог входа для команды 2.2 |
| C. Микрофреймворк (Slim) + библиотеки | Минимум чужого кода; MCP, очереди, авторизация и миграции пишутся руками — против срока MVP |
| D. Расширение монолита 1С-Битрикс (2.2) | Знакомо команде; но Платформа разворачивается в закрытом контуре с сегментацией DMZ/Internal (6.4, 7.1), внешний монолит в него не переносится |

## Решение

**Вариант A.** Laravel 13.x на PHP 8.3. Два контейнера в `kb-internal`: `kb-app` (php-fpm за существующим `kb-nginx`) и `kb-worker` (обработчик очередей); образ, версия и sha256 — в `infra/main.tf` (ADR-0001).

Условия реализации:

- MCP-сервер объявляется как `Mcp::web('/mcp', …)` в `routes/ai.php`.
- Streaming: генератор отдаёт `Response::notification(...)` на стадиях retrieval и rerank, а текст ответа — одним `Response::text(...)` **после** выходных guardrails. Потоковая выдача токенов до проверки запрещена: FR-8 требует контроля полного ответа, и это ограничивает FR-6 прогрессом стадий.
- Трейсы (7.9, FR-9) — OpenTelemetry SDK в `kb-app` и `kb-worker`, экспорт OTLP в `kb-alloy` (ADR-0015), оттуда в Tempo (ADR-0004).
- SSE-соединение занимает процесс php-fpm на всё время ответа: размер пула считается от ≥ 10 одновременных пользователей (6.1) и входит в Capacity Planning (7.10).

## Последствия

Плюс: обязательство 7.8 закрывается пакетом, который сопровождается вместе с фреймворком; FR-6 не требует собственного транспорта; FR-1 получает очередь и статусы без отдельного брокера; интерфейс blob-хранилища из ADR-0018 получает конкретного владельца.

Минус: `laravel/mcp` стал стабильным за неделю до решения — опыта эксплуатации v1 у рынка нет, а замена пакета означает переписывание транспортного слоя; мажорный релиз фреймворка раз в год — обязательство по обновлению для команды сопровождения (2.2); одна кодовая база на MCP-сервер и админ-панель означает общий пул php-fpm, где тяжёлый запрос админки конкурирует с бюджетом latency 6.1.

Точка ревизии — превышение бюджета 6.1 из-за занятости пула: тогда Octane или вынос MCP-сервера в отдельный контейнер на той же кодовой базе.
