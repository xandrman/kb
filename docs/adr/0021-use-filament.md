# ADR-0021: Админ-панель — Filament 5

Статус: принят  
Deciders: AI Architect  
Дата: 2026-09-22  
Техническая история: ТЗ-ТМ-2026-014, п. 2.2, 4.2, 4.3, 4.5, 5 (FR-1), 6.1, 6.3, 6.4, 7.6, 9.3

## Контекст

FR-1 задаёт админ-панель списком: аутентификация и авторизация через Keycloak, загрузка документов, асинхронная обработка с видимым статусом и повторной обработкой, список документов со статусами, статистика корпуса. П. 9.3 добавляет обязательные метаданные при загрузке — SKU, тип документа, гриф доступа, отдел-владелец (4.2). П. 6.4 ограничивает доступ ролью «администратор».

Фреймворк выбран ADR-0020, способ построения интерфейса — нет. Объём мал и фиксирован: один ресурс (документ) с формой загрузки, таблицей и двумя-тремя виджетами статистики; корпус — до 500 документов (4.5), пользователей админки — единицы.

## Драйверы

- **Форма FR-1 совпадает с тем, что генерируется.** CRUD-ресурс, таблица с фильтрами и виджеты описываются в Filament декларативно на PHP.
- **Ни одной строки JS в поставке (2.2).** Livewire держит состояние на сервере. SPA потребовала бы контейнера сборки фронтенда, отдельного контракта API и компетенции, которой у команды сопровождения нет.
- **Видимый статус (FR-1) без вебсокетов.** Периодический опрос таблицы средствами Livewire закрывает требование, не добавляя в контур ws-сервис.
- **Одна точка проверки роли (6.4).** Доступ к панели — `canAccessPanel()`, сверяющий claim роли из токена Keycloak; собственной системы прав у админки не появляется.
- **Air-gapped (6.3).** Ассеты публикуются локально на этапе сборки образа, CDN не требуется. Лицензия MIT.

## Варианты

| | Суть |
|---|---|
| **A. Filament 5** | Форма, таблица, виджеты и правило доступа декларативно; MIT; цена — крупная зависимость с мажором примерно раз в год |
| B. Laravel Nova | Тот же класс решений, first-party; платная лицензия на сайт — расход при наличии бесплатного эквивалента |
| C. Blade + Livewire вручную | Ноль лишних зависимостей; загрузка, таблица со статусами, фильтры и виджеты пишутся и поддерживаются самостоятельно |
| D. SPA (Vue/React) + API | Свободный UI; контейнер сборки, отдельный контракт API и отсутствующая компетенция (2.2) |

## Решение

**Вариант A.** Filament 5.x (PHP 8.2+, Laravel 11.28+) — панель `admin` внутри `kb-app` (ADR-0020); отдельного контейнера не появляется.

Условия реализации:

- Панель доступна по пути `/admin` за `kb-nginx`, отдельным хостом в DMZ не публикуется (6.4).
- Аутентификация — тот же OIDC-guard Keycloak, что и у MCP-эндпоинта (ADR-0020). `canAccessPanel()` возвращает истину только для роли «администратор» (6.4); таблица паролей не заводится.
- Форма загрузки обязывает заполнить SKU, тип документа, гриф доступа и отдел-владельца (9.3, 4.2). Файл уходит в blob-хранилище через интерфейс ADR-0018, метаданные пишутся в PostgreSQL (ADR-0014) одной транзакцией с постановкой задачи в очередь; повторная обработка ставит ту же задачу по существующему дайджесту, файл не перезагружается.
- Список документов и статусы читаются под RLS (ADR-0014); обновление статуса — опрос не чаще одного раза в 5 с.
- Ассеты собираются и публикуются на этапе сборки образа, `filament:optimize` — шаг сборки, не рантайма.
- Виджеты статистики считают по PostgreSQL; обращений в Qdrant и Neo4j из админки нет.

## Последствия

Плюс: FR-1 закрывается конфигурацией, а не интерфейсным кодом; в поставке нет ни сборки фронтенда, ни второго контейнера; правило доступа к админке выражено один раз и в одном месте.

Минус: самая крупная сторонняя зависимость прикладного слоя, с мажорным релизом примерно раз в год (v4 → v5 за год) и обязательством обновления на команде сопровождения (2.2); шаг в сторону от CRUD оплачивается борьбой с абстракцией; Livewire делает каждое действие формы round-trip'ом к `kb-app`, а пул php-fpm общий с MCP-сервером (ADR-0020) — загрузка крупного PDF конкурирует с бюджетом latency 6.1.

Не измерено: время отклика формы на файле верхней границы (до 100 страниц, 4.3) и его влияние на пул; объём ассетов Filament в образе; полнота русской локализации интерфейса.

Точка ревизии — появление у админки требований вне CRUD (например, интерактивного просмотра графа): отдельный интерфейс, а не обход абстракций панели.
