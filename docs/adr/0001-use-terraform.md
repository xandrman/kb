# ADR-0001: Развернуть инфраструктуру через Terraform

Статус: принят  
Deciders: AI Architect  
Дата: 2026-09-19  
Техническая история: ТЗ-ТМ-2026-014, п. 7

## Контекст

Платформа — on-premise, EPYC + 4×RTX 3090, закрытый контур (данные не покидают периметр). ТЗ (артефакт 6) требует docker-compose; Terraform — опционально. GPU-бюджет 96 GB, сеть DMZ/Internal, нет DevOps-команды в штате.

## Драйверы

- Воспроизводимость: пилот = приёмка, 1:1
- Явная GPU-аллокация (vLLM / embedding / reranker)
- Закрытый контур: данные не покидают периметр (152-ФЗ)

## Варианты

| | Суть |
|---|---|
| A. Compose only | Быстрый старт |
| B. Compose → Terraform позже | Двойная модель, рассинхрон |
| **C. Terraform + Docker provider** | Декларативно: сети, GPU, сервисы |

## Решение

**Вариант C.** Terraform покрывает compose-функционал + GPU/сети. K8s (вариант D/E) — избыточен при ≤10 пользователях.

## Последствия

Плюс:
- `terraform apply` = воспроизводимое окружение
- GPU-привязки и DMZ/Internal зафиксированы в коде
- Масштабирование Data Plane = `for_each`, не новый compose

Минус:
- Необходима установка Terraform + docker provider на целевом сервере
