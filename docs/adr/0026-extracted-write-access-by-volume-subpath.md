# ADR-0026: Запись результата извлечения — подкаталоги тома `kb-documents` с правами по ролям (частичное замещение ADR-0018)

Статус: принят  
Deciders: AI Architect  
Дата: 2026-09-23  
Техническая история: ТЗ-ТМ-2026-014, п. 2.2, 5 (FR-1, FR-2, FR-3, FR-5), 6.1, 6.4, 7.5, 7.6, 8.3

## Контекст

ADR-0018 задал раскладку тома `kb-documents`: `raw/<xx>/<sha256>` — оригинал, `extracted/<xx>/<sha256>.json` — DoclingDocument, результат ADR-0012. Там же распределены права: загрузчик админ-панели — `rw`, воркер и слой выдачи — `read_only`.

DoclingDocument появляется в воркере: по ADR-0012 маршрут выбирает и запрос в docling-serve отправляет воркер PHP, по ADR-0022 стадии ingest'а — задачи Laravel Queue (ADR-0020). Единственная роль, получающая результат извлечения, по ADR-0018 не может его записать, а единственная роль с правом записи результата не получает. Путь в ADR-0018 назначен, запись по нему — нет.

## Драйверы

- **Неизменяемость `raw/` — свойство конструкции, а не дисциплины.** Расследование расхождений (8.3) и воспроизводимость переиндексации (ADR-0018) опираются на то, что вход конвейера не менялся задним числом. Воркер обрабатывает недоверенный вход (сканы, PDF от Заказчика) и ходит в сеть — процесс, которому достаточно чтения оригинала, не должен иметь права его перезаписать.
- **Результат пишет тот, кто его получил.** Ответ docling на документ до 100 страниц (4.3) — десятки мегабайт JSON; передача его второму процессу ради записи — лишний транспорт и лишняя точка отказа.
- **Пул php-fpm общий с MCP (ADR-0020, ADR-0023).** Всё, что проводит крупный JSON через `kb-app`, конкурирует с бюджетом latency 6.1.
- **Атомарная публикация (ADR-0018).** Временный файл должен лежать на той же файловой системе и в той же доступной на запись области, что и цель.
- **Ни одного нового контейнера и хранилища (2.2, 7.5).**

## Варианты

| | Суть |
|---|---|
| **A. Подкаталоги одного тома с правами по ролям** | Воркер получает `raw/` только на чтение и `extracted/` на запись двумя подключениями одного тома (`subpath`); неизменяемость `raw/` обеспечивает ядро, а не код |
| B. Воркеру весь том `rw` | Одна строка в `infra/main.tf`; неизменяемость `raw/` держится только на коде — противоречит первому драйверу |
| C. Воркер отдаёт JSON в `kb-app`, пишет `kb-app` | Права ADR-0018 сохраняются буквально; цена — внутренний API, крупный JSON через пул php-fpm, общий с MCP (6.1) |
| D. Отдельный том под результаты извлечения | Та же изоляция, что в A; цена — второй том с отдельным бэкапом и изменённая раскладка ADR-0018 |
| E. DoclingDocument в PostgreSQL (JSONB) | Одна транзакция с реестром; цена — десятки мегабайт на документ в WAL и `pg_dump` (довод ADR-0018 против варианта C там), размер на сканах не измерен |

## Решение

**Вариант A.** Раскладка ADR-0018 не меняется; меняются права воркера.

| Роль | `raw/` | `extracted/` |
|---|---|---|
| Загрузчик админ-панели | `rw` | — |
| Воркер ingest'а | `read_only` | `rw` |
| Слой выдачи | `read_only` | `read_only` |

Условия реализации:

- Воркеру том подключается дважды, подкаталогами (`volume_options.subpath` в `infra/main.tf`), по тем же путям, что у остальных ролей: `/data/documents/raw` и `/data/documents/extracted`. Корень тома и его служебный каталог временных файлов воркеру не видны.
- Docker требует, чтобы подкаталог существовал к моменту подключения. `raw/` и `extracted/` с владельцем процесса приложения создаёт контейнер загрузчика при старте; воркер стартует после него.
- Публикация в `extracted/` атомарна: временный файл пишется внутри `extracted/` и переименовывается в цель. В отличие от `raw/`, перезапись допустима: DoclingDocument — производное представление, повторное извлечение (смена модели VLM-маршрута, ADR-0012) заменяет его. Какая версия конвейера его произвела, записывается в реестр (ADR-0018).
- Интерфейс blob-хранилища ADR-0018 дополняется операциями записи и чтения DoclingDocument с тем же ключом — дайджестом оригинала.

Остальное в ADR-0018 — раскладка, адресация по sha256, атомарность и дедупликация `raw/`, реестр в PostgreSQL, запрет раздачи через Nginx, порядок удаления, проверка целостности — остаётся в силе. Замещается только строка о правах воркера.

## Последствия

Плюс: воркер физически не может изменить оригинал — неизменяемость `raw/` обеспечивает ядро; результат извлечения записывается там, где получен, без передачи через `kb-app`; ни нового контейнера, ни нового тома.

Минус: подключение подкаталогов требует Docker Engine ≥ 26 и поддержки в провайдере Terraform — версия среды выполнения становится требованием к развёртыванию; появляется порядок старта (загрузчик создаёт подкаталоги до воркера); два подключения одного тома читаются в `infra/main.tf` хуже одного; перезапись `extracted/` не хранит прошлых извлечений — сравнить результат старой и новой модели на том же документе можно только до замены; загрузчик и слой выдачи живут в одном контейнере (ADR-0020), поэтому слой выдачи фактически получает права загрузчика — строка «слой выдачи» в таблице выполняется только после их разделения.

Не измерено: размер DoclingDocument относительно оригинала на сканах (наследуется из ADR-0018).

Точка ревизии — разделение загрузчика и слоя выдачи по контейнерам или переход на MinIO (ADR-0018): тогда права пересматриваются вместе с новой топологией.
