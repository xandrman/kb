# ADR-0034: API-спецификация MCP-сервера — ревизия MCP 2025-11-25 и самоописание `tools/list` вместо OpenAPI

Статус: принят  
Deciders: AI Architect  
Дата: 2026-09-24  
Техническая история: ТЗ-ТМ-2026-014, п. 2.2, 3.1, 6.5, 7.8, 8, 9.1, 10

## Контекст

П. 10 (позиция 5) требует положить в `/docs` «ER-модель + API-спецификацию», но не называет формат. Внешний контракт Платформы — MCP-эндпоинт `/mcp` (7.8, ADR-0020). Кроме него, `kb-app` публикует два HTTP-маршрута (ADR-0025): метаданные защищённого ресурса и backchannel logout.

MCP — это JSON-RPC 2.0 на одном пути. Методы `initialize`, `tools/list` и `tools/call` различаются полем `method` в теле запроса, а не путём и HTTP-методом. OpenAPI описывает операции через пути и HTTP-методы, поэтому MCP в нём сводится к одной операции `POST /mcp` с телом `oneOf` по `method`.

Ревизия протокола нигде не зафиксирована. `laravel/mcp` v1.0.0 (ADR-0020) обслуживает два вида рукопожатия:

- `initialize` для ревизий 2025-06-18 и 2025-11-25. На неизвестную ревизию сервер отвечает 2025-11-25.
- discovery для 2026-07-28, с версией протокола в `_meta` каждого запроса.

LibreChat (ADR-0024) подключается через `initialize`. Для него `McpServer::send()` убирает поля результата, которые появились в 2026-07-28. Feature-тесты `/mcp` закреплены на 2025-06-18. ADR-0024 и ADR-0025 ссылаются на страницы спецификации 2026-07-28, но на обязательность ревизии не претендуют.

## Драйверы

- **Потребитель API — хост MCP, а не разработчик интеграции** (7.8, 9.1). Хост получает список инструментов и их схемы от сервера во время работы, через `tools/list`. Документ в `/docs` он не читает.
- **Хост заменяем** (9.1, ADR-0024, ADR-0025). Стенд работает на LibreChat, пилот — на чате Заказчика, который ещё не назван. Нужна ревизия, которую понимают хосты, существующие сейчас.
- **Шов расширения** (6.5). Новый инструмент добавляется без переделки конвейера. Если его ещё нужно вручную вписать в отдельную спецификацию, появляется второй источник правды, и он расходится с кодом.
- **Сопровождение — PHP-команда без DevOps** (2.2). Каждый артефакт, который вручную синхронизируется с кодом, становится её обязанностью.
- **Приёмка** (8.6) проверяет полноту пакета документации. Позиция 5 п. 10 должна быть закрыта файлом в `/docs`, а не устным соглашением.

## Варианты

| | Суть |
|---|---|
| **A. Ссылка на ревизию MCP + снимок `tools/list`** | Протокол описан нормативным текстом MCP, инструменты — ответом самого сервера. Своего формата спецификации нет |
| B. OpenAPI 3.1 для HTTP-маршрутов + схемы инструментов в `components` | Тело `/mcp` не раскрывается и описывается ссылкой на MCP. Документ собирается командой из `Tool::toArray()`, расхождение ловит тест. Стандарт у маршрутов есть и так: RFC 9728 и OIDC Back-Channel Logout. Получается пересказ этих стандартов, который нужно поддерживать |
| C. OpenRPC | Формат создан для JSON-RPC, но описывает методы протокола, то есть дублирует спецификацию MCP. Инструментов MCP не знают ни хосты, ни инструменты OpenRPC |
| D. OpenAPI на весь протокол | `POST /mcp` с `oneOf` по всем методам MCP. Это пересказ спецификации MCP на языке, который для неё не предназначен |

Ревизии:

| | Суть |
|---|---|
| 2025-06-18 | На ней закреплены тесты. JSON Schema 2020-12 ещё не назначена диалектом схем по умолчанию, а метаданные сервера авторизации ищутся только по RFC 8414 |
| **2025-11-25** | Последняя ревизия с рукопожатием `initialize`, её понимают хосты, выпущенные до 2026 года. JSON Schema 2020-12 — диалект по умолчанию для `inputSchema`. Метаданные сервера авторизации ищутся и через OpenID Connect Discovery, которое Keycloak публикует штатно. `laravel/mcp` отвечает этой ревизией по умолчанию |
| 2026-07-28 | Ревизия по умолчанию в `laravel/mcp`, вышла за два месяца до решения. LibreChat из ADR-0024 её не использует, для чата Заказчика поддержка неизвестна. Продемонстрировать совместимость с ней на стенде нельзя |

## Решение

**Вариант A, ревизия MCP 2025-11-25.** OpenAPI-документация для `kb-app` не ведётся. API-спецификацией считается связка из четырёх частей:

1. спецификация MCP ревизии 2025-11-25 — транспорт Streamable HTTP, JSON-RPC, методы, уведомления `notifications/progress`, авторизация;
2. RFC 9728 для `GET /.well-known/oauth-protected-resource/{path}`;
3. OpenID Connect Back-Channel Logout 1.0 для `POST /mcp/backchannel-logout` (требования к logout token — в ADR-0025);
4. ответ `tools/list` сервера: имя, описание и `inputSchema` каждого инструмента.

Условия реализации:

- **Контрактная ревизия — 2025-11-25.** Совместимость с ней — обязательство поставки. 2025-06-18 и 2026-07-28 сервер принимает, потому что их поддерживает `laravel/mcp`, но обязательством они не являются. Обход в `McpServer::send()` сохраняется, пока контрактная ревизия использует `initialize`.
- **Тесты совместимости закрепляются на 2025-11-25.** Feature-тесты `/mcp` проверяют:
  - `initialize` с ревизией 2025-11-25 и её же в ответе;
  - `tools/list`;
  - `tools/call` инструмента `search` с уведомлениями о прогрессе.
  
  Тесты на 2025-06-18 остаются как проверка обхода для строгих клиентов.
- **Описание инструмента — часть спецификации.** У каждого инструмента есть:
  - `#[Description]`, по которому модель хоста понимает, когда вызывать инструмент и как понимать отказ;
  - `description` у каждого параметра в `schema()`.
  
  Если результат структурирован, объявляется `outputSchema()`. `search` возвращает текст, поэтому его не объявляет.
- **Позиция 5 п. 10 закрывается файлом `docs/api.md`.** Он содержит ревизию, три HTTP-маршрута со ссылками на стандарты и снимок ответа `tools/list` в `docs/api/tools-list.json`. Снимок не пишется руками: его выводит Artisan-команда, а feature-тест сверяет его с ответом сервера. Отладочные инструменты убираются из `McpServer` до сдачи, чтобы не попасть в снимок.

## Последствия

Плюс:
- у контракта один источник правды — код инструмента. Хост и снимок в `/docs` получают одно и то же, а расхождение снимка ловит тест;
- новый инструмент (6.5) не требует правки спецификации, кроме пересборки снимка;
- совместимость формулируется проверяемо: ревизия плюс тесты на ней. Отдельного формата и инструментов (Swagger UI, генераторы) в поставке нет;
- ревизия 2025-11-25 совпадает с тем, что понимают LibreChat и хосты, выпущенные до 2026 года.

Минус:
- тем, кто привык к OpenAPI, придётся читать спецификацию MCP. Интерактивной страницы с кнопкой «Try it out» нет, ручные вызовы делаются через `php artisan mcp:inspector`;
- интеграция не через MCP (обычный REST-клиент) спецификацией не покрыта;
- обязательство держится на поддержке `initialize` в `laravel/mcp`. Если пакет её уберёт, придётся либо остаться на старой версии пакета, либо сменить контрактную ревизию;
- формат ответа `search` описан текстом в `#[Description]`, а не схемой.

Не измерено: какую ревизию LibreChat из сборки ADR-0024 указывает в `initialize`; какие ревизии поддерживает чат Заказчика.

Точки ревизии:
- Заказчик называет чат, который не поддерживает 2025-11-25 — выбор новой контрактной ревизии;
- у Платформы появляется потребитель не через MCP — вариант B для его маршрутов;
- релиз `laravel/mcp` без рукопожатия `initialize` — пересмотр контрактной ревизии.
