# ADR-0005: Принять Grafana Loki как хранилище логов

Статус: принят  
Deciders: AI Architect  
Дата: 2026-09-19  
Техническая история: ТЗ-ТМ-2026-014, п. 5 (FR-9), 7.9, 8.4

## Контекст

ADR-0002 закрепляет источники данных Prometheus / **Loki** / Tempo; ADR-0003 — Alloy собирает и логи (`loki.source.*` → `loki.write`); ADR-0004 закладывает корреляцию трейс↔лог через метки Loki, но хранилища для логов ещё не было.

Требования: FR-9/8.4 — логи LLM-сервера видны из инструмента трейсинга, связаны с трейсом по `trace_id`. Закрытый контур (6.3), сегментация DMZ/Internal (6.4), нет DevOps в штате (2.2).

## Драйверы

- FR-9/8.4: переход от трейса к логам по `trace_id`
- Alloy (ADR-0003) уже пишет логи нативно через `loki.write`
- Минимум движущихся частей: нет DevOps, один хост
- Единая экосистема с Grafana OSS (ADR-0002): LogQL, производные поля

## Варианты

| | Суть |
|---|---|
| **A. Grafana Loki** | Индекс только по меткам → дёшево; нативно с Alloy и Grafana; единая экосистема ADR-0002/0003/0004 |
| B. ELK | Полнотекстовый индекс, но тяжёлый (JVM); собственный интерфейс; корреляция с Tempo — вручную |
| C. Только stdout/journald | Не выполняет 8.4, не масштабируется |
| D. SaaS | Нарушает 6.3/152-ФЗ — **исключён** |

## Решение

**Вариант A.** Loki — хранилище логов. Alloy собирает контейнерные логи и логи Nginx (`loki.source.docker`/`loki.source.file`) и пишет их через `loki.write`; хранение — **локальный том** (`filesystem`, без S3/MinIO в MVP).

```
Nginx / vLLM / MCP (PHP)  ──▶  Alloy (loki.source.* → loki.process → loki.write)
                                     │
                                     ▼
                                   Loki  ──▶  локальный том
                                     │
Grafana OSS  ◀── источник данных ────┘  (LogQL, производное поле trace_id → Tempo)
```

- Контейнер `kb_loki`, сеть `kb_internal`, без публикации портов хоста (6.4).
- Производное поле в Grafana: regex `trace_id=(\w+)` → ссылка на Tempo (8.4).
- Корреляция: Alloy извлекает `trace_id`/`span_id` из логов Nginx (`otel_trace_context propagate`, ADR-0004) через `loki.process`/`stage.regex`.
- Метки — низкокардинальные (`service_name`, `container`, `level`); `trace_id`/`request_id` — в структурированные метаданные, не в метки.

**Параметры MVP:** срок хранения 30 дней (как Tempo); хранилище `filesystem`; монолитный режим (`-target=all`).

**Лицензия.** AGPL-3.0 — допустимо, как и Grafana/Alloy/Tempo (ADR-0002–0004): используем дистрибутив как есть.

## Последствия

Плюс:
- Закрывает третий столп наблюдаемости из ADR-0002 (Prometheus/метрики — ещё открыт)
- FR-9/8.4 выполнено: логи доступны из Tempo через производное поле
- Один агент (Alloy) вместо отдельного promtail-конвейера
- Дешёвое хранение, развёрнуто локально в закрытом контуре (6.3)

Минус:
- AGPL-3.0: нет редистрибуции модификаций
- Не полнотекстовый индекс — нерегламентированный поиск по содержимому медленнее, чем в ELK
- Дисциплина меток критична (неверная кардинальность деградирует производительность)
- Монолитный режим — единая точка отказа для логов (отказоустойчивость — за пределами MVP)
