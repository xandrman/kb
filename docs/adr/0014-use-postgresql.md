# ADR-0014: Реляционная БД — PostgreSQL 18

Статус: принят  
Deciders: AI Architect  
Дата: 2026-09-20  
Техническая история: ТЗ-ТМ-2026-014, п. 2.2, 4.2, 5 (FR-1, FR-7), 6.2, 6.3, 6.4, 6.5, 7.5, 7.6, 7.10, 8.3

## Контекст

Из четырёх хранилищ п. 7.5 закрыты два: векторное (ADR-0006) и графовое (ADR-0007). Реляционное — «метаданные, пользователи, сессии, аудит» — не выбрано, и ADR-0006 зафиксировал это долгом: метаданные «предполагаются в PostgreSQL», решения не принималось. На нём держатся статусы асинхронной обработки (FR-1), метаданные документа и источник значения `access_level` (4.2), сопоставление ролей Keycloak с документами (FR-7, 8.3), аудит-лог доступа к ограниченным документам (6.4) и ER-модель — обязательный артефакт поставки (7.10, артефакт 5), который до выбора СУБД не нарисовать. Сами пользователи и их роли остаются в Keycloak и приходят в токене (7.8): вопреки слову «пользователи» в п. 7.5, PostgreSQL каталог не дублирует — от пользователя здесь остаётся идентификатор субъекта в аудит-логе. Масштаб мал: 125–500 документов, 10–50 тыс. чанков, ≤ 10 пользователей — производительность кандидатов не различает. Против очевидного выбора работает контекст Заказчика: Битрикс на MySQL и сильная PHP-команда (2.2).

## Драйверы

- **RLS — единственное место в стеке, где забытая проверка прав не даёт утечки.** В Qdrant фильтр по грифу кладёт в запрос приложение (ADR-0006), в Neo4j Community предикат пишется в тексте Cypher (ADR-0007 записал это в минусы) — в обоих случаях гарантией служит дисциплина разработчика. Политика RLS живёт на таблице и подставляется планировщиком, даже если в коде условия нет. У MySQL и MariaDB RLS нет — эквивалент собирают из view с `DEFINER`, функций и триггеров, то есть та же дисциплина, только размазанная по объектам БД
- **Гриф доступа хранится в трёх местах — у него должен быть один владелец.** `access_level` лежит в метаданных документа, в payload Qdrant (ADR-0006) и в свойствах узлов Neo4j (ADR-0007): каждому хранилищу он нужен локально для фильтрации при поиске. Владельцем назначается реляционная БД, две копии — производные. Смена грифа и постановка чанков в очередь на переиндексацию выполняются одной транзакцией: сбой между шагами оставил бы копии расходящимися навсегда, а расхождение здесь — утечка по п. 8.3, а не рассогласование данных. До завершения переиндексации документ считается недоступным
- **Опыт команды с MySQL не переносится:** это эксплуатация готовой схемы Битрикса, а схему Платформы проектируем мы; для PHP разница сводится к `pdo_pgsql` вместо `pdo_mysql`
- **Лицензия кандидатов не различает.** GPLv2 у MySQL/MariaDB допустим по той же логике, которой ADR-0007 обосновал Neo4j GPLv3 — сетевой сервис без модификации. Названо, чтобы не выглядело решающим

## Варианты

| | Суть |
|---|---|
| **PostgreSQL 18** | RLS в ядре; JSONB + GIN под «шов расширения» (6.5); партиционирование; `uuidv7()`; PostgreSQL License |
| MySQL 8.x / MariaDB 11.x | Знакомы команде (2.2); RLS нет — только view + `DEFINER`; GPLv2 |
| SQLite | Один писатель на файл — конфликт с 6.2 (параллельная обработка ≥ 2 документов); нет ролей и RLS |
| Без реляционной БД: всё в payload Qdrant и свойствах Neo4j | Минус контейнер, но и минус ACID, аудит (6.4), статусы FR-1 — три копии грифа без владельца |

## Решение

**PostgreSQL 18** (stable 18.6; ветка 19 на дату решения в beta 3 — в MVP не берём, обновление после приёмки). Контейнер `kb_postgres`, сеть `kb_internal`, без публикации портов (6.4), версия и sha256 — в `infra/main.tf`; TLS `ssl = on`, PHP с `sslmode=verify-full`, пароль роли из Vault (паттерн ADR-0007).

Роли не хранятся — их приносит токен Keycloak (7.8); PostgreSQL хранит сопоставление роли с документами, и политика RLS сверяет строку с ролями запроса через это сопоставление. RLS включается с `FORCE ROW LEVEL SECURITY`, приложение подключается ролью, не владеющей таблицами: иначе владелец обходит политику. Аудит 6.4 — прикладная таблица, а не `pgaudit`: тот пишет SQL от имени роли приложения, где нет ни сотрудника, ни вопроса, ни использованных чанков.

## Последствия

Плюс: RBAC на метаданных обеспечивает СУБД, а не аккуратность разработчика; закрыт долг ADR-0006; разблокированы ER-модель и API-спецификация; JSONB даёт «шов расширения» (6.5) без миграций; на одно лицензионное обоснование меньше в артефакте 2.

Минус: четвёртый stateful-контейнер, а опыт команды (2.2) лежит вокруг MySQL — порог входа в эксплуатации (autovacuum, роли, `pg_dump`), не в SQL; **RLS защищает только метаданные** — тексты чанков в Qdrant и связи в Neo4j остаются на MCP-сервере, тесты п. 8.3 не отменяются, есть риск ложного чувства защищённости; одно правило доступа выражено в трёх синтаксисах (политика, `Filter` Qdrant, предикат Cypher) — рассинхрон ловится только тестом; без HA, восстановление из дампа — пересмотр вместе с Neo4j при масштабировании.

Не измерено: объём аудит-лога на пилоте; накладные расходы политик RLS на планы запросов; RAM под PostgreSQL в Capacity Planning (7.10) вместе с JVM Neo4j.
