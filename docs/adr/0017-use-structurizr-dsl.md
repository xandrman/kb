# ADR-0017: Диаграммы как код — Structurizr DSL для C4, Mermaid для ER и Sequence

Статус: принят  
Deciders: AI Architect  
Дата: 2026-09-22  
Техническая история: ТЗ-ТМ-2026-014, п. 2.2, 6.4, 7.10, 8.6, 8.8, 10 (артефакт 1)

## Контекст

ТЗ (7.10) требует шесть диаграмм: C4 L1–L3, Deployment, Sequence, ER. Все входят в поставку (п. 10, артефакт 1) и идут на приёмку (8.6). Формат не выбран ни одним из ADR-0001–0016.

Масштаб L2 известен снизу: в `infra/main.tf` (ADR-0001) четырнадцать контейнеров без MCP-сервера, админ-панели, PostgreSQL (ADR-0014), Vault, очереди и guardrails — итого порядка двадцати узлов в сегментах DMZ/Internal (6.4). Ревью идёт через pull request в монорепо (8.8); сопровождение после сдачи принимает PHP-команда без DevOps (2.2).

## Драйверы

- **Согласованность L1–L3 — связывающее ограничение.** В модели сущность объявляется один раз, виды её проецируют; в инструменте рисования рассинхрон трёх файлов ловится только на ревью.
- **Двадцать узлов на L2.** Mermaid раскладывает их сеткой с единственной ручкой `$c4ShapeInRow`; в модели объём режется группами и фильтрованными видами.
- **ER и Sequence вне C4.** ER — модель данных (источник — схема PostgreSQL, ADR-0014). Sequence по 7.10 — цепочка Keycloak → Guardrails → RBAC → RAG → Rerank → LLM, которой нужны линии жизни, а не нумерованные связи.
- **Ревью в pull request.** GitHub рендерит Mermaid нативно, Structurizr DSL и PlantUML — нет.
- **Лицензии.** Structurizr — Apache 2.0, Mermaid и макросы C4-PlantUML — MIT, движок PlantUML — GPLv3, причём сгенерированные изображения лицензией не покрываются. Различающим фактором не является.

## Варианты

| | Суть |
|---|---|
| A. Mermaid на все шесть | Ноль тулчейна, рендер в GitHub; но C4 имеет статус experimental с заявленной нестабильностью синтаксиса, а раскладка управляется единственной ручкой `$c4ShapeInRow` — L2 нужного размера нечитаем |
| B. C4-PlantUML на все шесть | Единственный, кто закрывает все шесть одним тулчейном; модели нет — согласованность держится на авторе; требует Java и Graphviz, в GitHub не рендерится |
| **C. Structurizr DSL для C4 + Mermaid для ER и Sequence** | Согласованность гарантирована моделью; два не-C4 артефакта видны прямо в PR; цена — две нотации и C4 без просмотра в репозитории |

## Решение

**Вариант C.**

Источник правды для C4 — `docs/architecture/workspace.dsl`. Виды: `systemLandscape`, `systemContext` (L1), `container` (L2), `component` для MCP-сервера (L3), `deployment` с сегментами DMZ/Internal (6.4). Dynamic view не используется, чтобы флоу 7.10 не жил в двух несогласуемых представлениях.

ER и Sequence — Mermaid: `docs/diagrams/er.mmd` и `docs/diagrams/sequence-query.mmd`.

Отрисовка не автоматизируется и в репозиторий не попадает: хранится только исходный код диаграмм. Инструмент просмотра выбирает тот, кому он понадобился; `workspace.json` с ручной раскладкой не ведётся.

Условия реализации:

- Удалённые темы не подключаются — стили объявляются в `workspace.dsl`.
- L2 и Deployment сверяются с `infra/main.tf` (ADR-0001); расхождение с кодом — дефект диаграммы.

Точка ревизии — момент, когда L3 MCP-сервера перестанет укладываться в component view.

## Последствия

Плюс: уровни C4 не расходятся — переименование правится в одной строке; ER и Sequence ревьюируются по diff наравне с кодом; в `docs/` нет производных файлов, которые расходятся с источником.

Минус: две нотации вместо одной и порог входа выше, чем у чистого Mermaid (2.2); C4-диаграммы в репозитории существуют только как текст — чтобы их увидеть, нужен внешний инструмент; раскладка L2 каждый раз автоматическая, её читаемость на ~20 узлах не гарантирована.
