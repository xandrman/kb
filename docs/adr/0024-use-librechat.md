# ADR-0024: Хост MCP для разработки и демонстрации — LibreChat, сборка из ветки прогресса

Статус: принят  
Deciders: AI Architect  
Дата: 2026-09-22  
Техническая история: ТЗ-ТМ-2026-014, п. 2.2, 5 (FR-5, FR-6, FR-7), 6.1, 6.3, 6.4, 7.8, 8, 9.1

## Контекст

П. 2.2 фиксирует у Заказчика self-hosted чат с LLM, но не называет продукт; 9.1 запрещает свой интерфейс. Хост MCP нужен нам — для разработки MCP-сервера (ADR-0020) и для приёмки (8), где 7.8 показывается на стороннем хосте, а не на самописном клиенте.

Стенд проверяет то, чего нет внутри Платформы: **путь токена** — access token Keycloak доходит от чата до MCP-сервера и определяет RBAC (7.8, FR-7); **видимость стадий** — ADR-0020 запрещает поток токенов до выходных guardrails, поэтому до последнего сообщения живой ответ виден только по `notifications/progress` (MCP 2026-07-28), которые `kb-app` уже шлёт, а отображает хост.

## Драйверы

- **Прогресс.** У hf chat-ui он в `main` (PR #2030 смержен 07.01.2026, рендер в `ToolUpdate.svelte`) — вопреки исходному допущению сравнения. У Open WebUI обработки нет. У LibreChat в `main` тоже нет, но есть две открытые PR мейнтейнера от 13.07.2026: #14241 (карточка tool-call) поверх #14240 (фоновые вызовы); ветка `claude/mcp-progress-ui` покрывает оба сценария.
- **Путь токена штатен только у LibreChat:** `Authorization: Bearer {{LIBRECHAT_OPENID_ACCESS_TOKEN}}`, заголовки пересчитываются перед каждым вызовом, продление — `OPENID_REUSE_TOKENS` со scope `offline_access`, роль — `OPENID_REQUIRED_ROLE`.
- **У альтернатив его нет.** chat-ui форвардит только токен Hugging Face, OAuth 2.1 для MCP — открытая PR #2250. Open WebUI знает none, bearer и OAuth 2.1 (DCR или static), а шаблоны заголовков дают `{{USER_ID}}`, `{{USER_EMAIL}}`, `{{USER_ROLE}}`, но не access token IdP: либо доверять полям хоста (FR-7 на этом не строится), либо поднимать свой authorization server.
- **Временный патч дешевле постоянного.** Недостающее у LibreChat ведёт мейнтейнер и закроет мержем; патч в обязательном FR-7 мы держали бы весь срок сопровождения (2.2).
- **Лицензии (6.3):** MIT у LibreChat, Apache-2.0 у chat-ui, у Open WebUI — не-OSI: BSD-3 плюс запрет менять брендинг при более чем 50 пользователях за 30 дней.

## Варианты

| | Суть |
|---|---|
| **A. LibreChat, сборка из ветки #14241** | MIT; проброс токена штатный; прогресс — на неслитой ветке; цена — своя сборка |
| B. hf chat-ui | Apache-2.0, прогресс уже в UI; проброс токена держим мы — постоянный патч в FR-7 |
| C. Open WebUI | Нативный MCP и per-user OAuth 2.1; прогресса нет, токен IdP не доходит, лицензия не-OSI |
| D. Без хоста: `mcp:inspector` и свой клиент | Ноль зависимостей; не проверяет ни 7.8 целиком, ни отображение прогресса |

## Решение

**Вариант A.** Контейнер `kb-librechat` в закрытом контуре: сеть `kb-internal` для доступа к `kb-nginx` и Keycloak, выхода в интернет нет; снаружи стенд доступен только через `kb-nginx` по TLS (6.4). Готового образа нет: опубликованные пакеты собираются из `main` и `dev`, коммитов ветки среди тегов не публиковалось. Собираем сами из `Dockerfile` на коммите `bad0b016b7c054640e38c0630880494971ae6435` форка `xandrman/LibreChat` (MIT) — head #14241 `d7a7375` плюс наш коммит, сужающий ключ прогресса до идентификатора шага. Имя образа и sha256 — в `infra/main.tf` (ADR-0001), автоматического переезда на новые коммиты нет.

Условия реализации:

- MCP — Streamable HTTP на опубликованный путь `/mcp` (ADR-0020) с `Authorization: Bearer {{LIBRECHAT_OPENID_ACCESS_TOKEN}}`; вход — Keycloak realm `kb` (`OPENID_*` со scope `offline_access`, `OPENID_REUSE_TOKENS=true`), локальная регистрация выключена. Источник прав — подпись токена, проверяемая `kb-app`, а не поля, подставленные хостом (FR-7).
- Провайдер модели в `librechat.yaml` один — `http://kb-vllm-generate:8000/v1` (ADR-0008); облачные эндпоинты выключены. В `kb-nginx` эндпоинт vLLM не публикуется.
- Из compose'а upstream разворачивается только MongoDB 8; `meilisearch`, `vectordb`, `rag_api` — нет: ретривал наш (ADR-0006, ADR-0007).
- Air-gapped (6.3) распространяется и на стенд: исходники форка зеркалируются в git контура, образ переносится в локальный registry, отсутствие исходящего трафика проверяется на приёмке вместе с остальными контейнерами `kb-internal`.
- Стенд не входит в поставку: критерии 9.4 меряются на штатном чате Заказчика, на стенде — 7.8 и видимость стадий. Наш коммит уходит в #14241 как review feedback: место патча — upstream, а не личный форк.

## Последствия

Плюс: 7.8 проверяется целиком — от входа через Keycloak до RBAC на чанках; уведомления `kb-app` становятся видимыми и показывают, где стоит длинный ответ (6.1); замена стенда на чат Заказчика не затрагивает `kb-app`.

Минус: ветка не слита и конфликтует с `dev` (`mergeable_state: dirty`), живёт в личном форке — при закрытии PR патч переносим сами, при мерже upstream'ом своей версии наш коммит снимаем; исправления безопасности приходят пересборкой, а не обновлением тега; стенд тянет MongoDB — СУБД вне ADR-0014 и ADR-0019; стенд внутри контура обновляется только пересборкой из зеркала, то есть его сопровождение ложится на ту же команду, что и Платформу; хоста LibreChat у Заказчика может не оказаться, и часть проверки 7.8 повторится на штатном чате.

Не измерено: прогресс при ≥ 10 одновременных пользователях (6.1) и задержка от throttling'а эмиттера в #14241; прохождение заголовка с токеном и потока SSE через `kb-nginx`.

Точка ревизии — мерж #14241 и #14240 в `dev` и релиз с прогрессом: переход на официальный образ по тегу. Второй триггер — Заказчик называет свою систему диалогов: её способность передавать токен и отображать прогресс проверяется отдельно.
