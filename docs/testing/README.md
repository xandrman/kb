# Реестр публичного корпуса

Справочный документ. Не ADR, решений не фиксирует и на ADR не ссылается. Описывает `registry.json` —
перечень публичных документов, из которых собран компонент 2 пилотного корпуса (ТЗ, п. 4.5).

`registry.json` в этом каталоге — копия `testdata/registry.json`. Каталог `testdata/` в `.gitignore`:
сами PDF в репозиторий не попадают, здесь только ссылки на них.

## Итог

| | |
|---|---|
| Источник | `data.nag.wiki` — открытые руководства и паспорта оборудования SNR |
| Записей | 107, из них в корпусе 100 (`in_corpus: true`) |
| Страниц в корпусе | 1 688, до 52 на документ |
| Типы документов | 48 паспортов оборудования, 37 руководств, 15 инструкций |
| Грифы | 93 публичных, 7 служебных |
| Отделы-владельцы | 48 — отдел продаж, 45 — служба поддержки, 7 — сервисный центр |

Синтетические сервисные акты (компонент 1) в реестр не входят: их метаданные — в
`testdata/synthetic/manifest.json`, генерация — «Синтетические сервисные акты.md». Манифест содержит
сгенерированные ПДн и не публикуется.

## Поля записи

| Поле | Значение |
|---|---|
| `url` | Прямая ссылка на PDF на `data.nag.wiki` |
| `filename` | Имя файла в `testdata/`; под ним документ загружается в систему |
| `pages` | Число страниц |
| `in_corpus` | Входит ли документ в пилотный корпус |
| `processing_test` | Необязательное; `true` — документ для замера обработки одного документа |
| `sku` | Модель или серия техники |
| `document_type` | Тип документа: «Паспорт оборудования», «Руководство», «Инструкция» |
| `access_level` | Гриф: `public` или `internal` |
| `owner_department` | Отдел-владелец |
| `document_date` | Дата документа, `ГГГГ-ММ-ДД` |

`sku`, `document_type`, `access_level`, `owner_department` и `document_date` — метаданные, которые
админ-панель требует при загрузке (ТЗ, п. 9.3). Производитель их не публикует: они назначены вручную
для тестирования.

## Грифы

Все документы реестра открыты на сайте производителя. Гриф `internal` у семи из них — тестовая
разметка для проверки разграничения доступа, а не признак служебного документа:

- `Типовая_схема_параллельного_подключения_ИБП_с_общей_АКБ.pdf`
- `Чертеж SNR-PDU-A-36A06B-32L3.pdf`
- `Чертеж SNR-PDU-D-18A06B-32L3.pdf`
- `R_Adm_SNR-ERD-2.3.pdf`
- `R_Adm_SNR-ERD-2s.pdf`
- `Описание интеграции устройств серии SNR-ERD с системой Macroscop.pdf`
- `Руководство по использованию SNR-Eth-MBus ver. 0.1.pdf`

## Документы вне корпуса

Семь документов длиннее 60 страниц (63–115) записаны с `in_corpus: false`. Один из них —
`Руководство_пользователя_ИБП_SNR_серии_SM_100-500_кВА_EN.pdf` (92 страницы, `processing_test: true`) —
использован для замера обработки одного документа, близкого к пределу ТЗ п. 6.2 в 100 страниц
(«Нагрузочный отчёт.md»).

## Как повторить

1. Скачать файлы по `url` в `testdata/` под именами из `filename`.
2. Положить реестр в `testdata/registry.json`, синтетические акты — в `testdata/synthetic/`.
3. Загрузить корпус командой `testdata:import --uploader=<e-mail администратора>`
   (`backend/app/Console/Commands/ImportTestCorpus.php`). Команда берёт записи с `in_corpus: true`
   и акты из манифеста и загружает их тем же путём, что админ-панель; уже загруженные файлы пропускает.
